Codex CLI 被指默认常驻后台守护进程，冲上 HN 首页

🏷 博主解读

🕐 时间：北京时间 10月13日傍晚（Hacker News 讨论冲上首页，检索时 367 points、205 条评论；议题源自 GitHub 上 9月25日提交的 issue #48195；原文未注具体时刻）

GitHub 上 openai/codex 仓库的 issue 指出：自 Codex CLI 0.157.0 起，打开交互式会话会默认启动常驻后台守护进程（codex app-server --managed-daemon）——它会把约 374MB 的平台包复制到 ~/.codex 目录、随会话关闭继续运行，启动每小时检查一次的自动更新循环（可能强制中断进行中的对话），还会固定首个会话的环境变量（如代理配置）。发起者建议将 daemon_auto_start 改为显式「选择加入」，相关讨论随后登上 Hacker News 首页。

出处 GitHub · openai/codex Issue #48195 · Hacker News 讨论

QGIS 通过 QEP428：正式禁止 AI 生成/辅助贡献

🏷 官方披露

🕐 时间：10月13日（Hacker News 首页讨论；提案投票于本周通过——原文未注具体时刻）

开源地理信息系统 QGIS 的官方提案 QEP428「No ai contributions permitted」通过核心维护者投票（多名成员投出 +1），取代此前要求披露 AI 使用、保持「human in the loop」的 QEP408，即刻生效：不接受 LLM/AI/智能体辅助的代码贡献，事后发现将对相关代码回滚并限制贡献者权限。背景是此前约 50 个带「AI Assisted」标签的 PR 中约 40 个未获合并，维护者称 AI 生成补丁带来难以承受的评审负担；据社区整理，IDE 自动补全在开发者自行控制每一行的前提下仍被允许，政策细节或在 QGIS 用户大会上再作调整。

出处 GitHub · QEP428: No AI contributions permitted（PR #387） · Hacker News 讨论

哈佛研究：AI 编程智能体产出更多代码，软件产出却未见增长

🏷 媒体解读

🕐 时间：10月13日（Ars Technica 报道，当日在 Hacker News 引发讨论；原文未注具体时刻）

Ars Technica 报道，哈佛研究者 Fiona Chen 与 James Stratton 基于 Jellyfish 数据（3 亿条工程活动记录、700+ 家公司、70 万+ 员工，2021 年至 2026 年 3 月）发现：引入 AI 编程智能体后，代码总行数平均增加 30%、提交数增加 20%、PR 增加 23%，但 Jira 中 Issue/Epic 的解决率无显著变化；平均评审时间拉长 49%，要求修改的 PR 占比近乎翻倍、每条 PR 的评论数增加 35%，参与评审的员工占比上升 14%，且研究未发现显著就业变化。

出处 Ars Technica · AI coding agents generate more code, but not more software · Hacker News 讨论
